# Flight search UX

Цель: быстрее понять маршрут и сравнить рейсы.  
Не клонировать Google Flights / Aviasales / Kayak.

## Главная: поиск рядом с глобусом

- Глобус остаётся **видим**. Клик по городу и дуга маршрута — часть продукта.
- Поиск не перекрывает глобус плотным фото или тёмным градиентом.
- Поля в логическом порядке: Откуда → Куда → Даты → Пассажиры → Найти.
- После выбора городов дуга на глобусе синхронизирована (уже есть — не ломать `onCityClick` / origin-destination).

## Даты

- Round-trip по умолчанию привычен; one-way не прятать.
- Календарь + ручной ввод ([NN/g date input](https://www.nngroup.com/articles/date-input/)).
- Если позже появятся «±3 дня» / цена по дате — это **дополнение** к календарю, не замена глобуса и не отдельная страница.

## Пассажиры и класс

Короткий popover, ясные лимиты (младенцы ≤ взрослые — если правило уже в коде, не менять смысл, только подпись ошибки).

## Сохранение запроса

Query string / возврат на `/?fromIata=&toIata=&dateOut=…` должен выживать.  
Источник паттерна: отраслевой стандарт + [PHPTravels 2026](https://phptravels.com/blog/best-practices-for-flight-search-functionality-in-2026/).

## Выдача

Пользователь сравнивает, не «открывает сюрприз».

Обязательный набор в карточке (если данные уже приходят с API — показать, не выдумывать):

- Цена (и что в неё входит, если известно)
- Пересадки / прямой
- Общее время
- Багаж
- Авиакомпания
- Время в пути vs время стыковки — не смешивать в одну цифру без подписи

Источник: [Baymard Airlines UX Benchmark 2025](https://baymard.com/blog/airlines-ux-benchmark-2025).  
Источник: [Lyssna Booking vs Expedia](https://www.lyssna.com/blog/booking-vs-expedia/).  
Источник: [Baymard hidden costs](https://baymard.com/blog/current-state-of-checkout-ux) — не прятать сборы.

## Сортировка и фильтры

Типичный набор (визуально прояснить то, что уже есть):

- Цена / длительность / вылет
- Пересадки
- Багаж
- Время суток

Пустой результат: «Нет рейсов по фильтрам» + сброс. Не молчаливый blank.

Источник: [ScienceDirect 2025 Traveloka vs Tiket](https://www.sciencedirect.com/science/article/pii/S1877050925000808) — баланс простоты и контроля.  
Источник: [Baymard 2025](https://baymard.com/blog/airlines-ux-benchmark-2025).

## Ошибки поиска

«Нет такого IATA», «выберите дату», «куда = откуда» — у поля, не toast внизу экрана.

Источник: [NN/g web forms](https://www.nngroup.com/articles/web-form-usability/); [WCAG 3.3.1](https://www.w3.org/TR/WCAG22/#error-identification).

## Чего не делать

- Не уводить поиск на отдельный URL без глобуса «как у агрегаторов».
- Не добавлять 15 маркетинговых бейджей на карточку («суперцена», «хит», «горящий»).
- Не менять контракт API «чтобы карточка была красивее».
